# Можливі зловживання та запобіжники

Прототип призначений для навчального обговорення. Наведені механізми перевіряються автоматичними тестами, але не є сертифікацією безпеки чи гарантією від усіх атак.

| Ризик | Реалізований технічний запобіжник | Організаційна вимога та залишкова межа |
|---|---|---|
| Використання результатів для атестації, покарання або рейтингу | Немає загальної суми трьох шкал; немає адміністративного API чужих відповідей; SCORM передає лише статус, а агрегати — лічильники без `userId` | Заборонити кадрове використання інструкцією заняття. Адміністратор файлового хоста технічно має доступ до його даних; архітектура не захищає від власника сервера |
| Деанонімізація голосування | Код/QR без обов’язкового входу; акаунт не прив’язаний до голосу; кімнати в RAM; немає списку імен чи рейтингів | Не просити підписувати вибір, не фотографувати телефони, не робити персональних висновків із малої групи. Малий агрегат може дозволити контекстний здогад |
| Підміна голосів | Один голос на анонімний токен у поточному раунді, відновлення токена в тій самій вкладці | Токен не посвідчує фізичну особу: нові браузерні сесії можуть створити нових гостей. Потрібні правила заняття та контроль ведучого |
| Перехоплення керування | Криптографічний `hostSecret`, перевірка через `timingSafeEqual`, секрет у sessionStorage ведучого, не в QR | Не передавати секрет і не користуватися спільною вкладкою ведучого; HTTP у LAN не шифрується |
| Перевантаження HTTP/WS | Ліміти запитів; WS до 16 KiB, перевірка Origin, обмеження сокетів/кімнат, ліміт повідомлень | Ліміти локальні для процесу, не заміна мережевого захисту; публічне масштабування потребує окремої інфраструктури |
| Потрапляння ПД або службової інформації в кейси/нотатки | Немає полів ПІБ, звань чи контактів; дані сценарію відокремлені від коду; гостьовий доступ | Вільний текст технічно може містити чутливі дані. Автор і власник нотаток мають їх не вводити; перед публікацією потрібне людське рев’ю |
| XSS, ін’єкції SCORM, забруднення прототипів | React/DOM textContent, безпечне кодування JSON у SCORM, перевірка URL, відхилення `__proto__`/`constructor`/`prototype`, обмеження JSON/імпорту | Валідний JSON не доводить безпечність або правдивість юридичного змісту; зовнішні правові сайти не контролюються застосунком |
| Компрометація локального акаунта | Асинхронний `scrypt` із сіллю, підписана сесія з терміном дії, HttpOnly, SameSite=Strict, перевірка Origin/Referer для змін стану | Cookie Secure залежить від HTTPS. Довірена LAN або контрольований TLS-проксі потрібні для захисту пароля в мережі |
| Витік сховища | Статика лише з `dist/`; закриті внутрішні шляхи й dotfiles, каталог даних поза Git, права 0600, атомарний запис | Обмежити права адміністратора й резервні копії; не запускати кілька процесів з одним файловим сховищем |
| Хибна «оцінка особистості» ШІ | Детермінований JSON-двигун без LLM у runtime; аналіз дії та наслідків | Не переносити навчальні шкали в персональну характеристику. Людська перевірка необхідна для змісту й права |
| Перебільшення статистики | `aggregateStats` не містить логінів, токенів, нотаток і сирих шляхів; POST перевіряє завершений маршрут та має rate limit | Це кількість спроб, не унікальних людей; зловмисні повторні подання можливі. Статистика не репрезентативне соціологічне дослідження |

## Життєвий цикл і перевірка

Кімнати очищуються за чотири години неактивності та після перезапуску сервера; завершення розбору не слід плутати з негайним видаленням усіх даних кімнати. Локальні акаунти, прогрес та агрегати зберігаються у файловому сховищі, а не в кімнаті. Сервер бачить мережеву адресу підключення; тимчасові IP-лічильники захисту існують у RAM і не записуються в агрегати.

Перевірки: `npm test`, `npm run test:security:browser`, `npm run test:product`. Історична детальна [технічна записка](security-hardening.md) збережена окремо; інструкції розгортання — в [README](../README.md).

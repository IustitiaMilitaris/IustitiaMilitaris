# Користувацькі сценарії

Конструктор зберігає S04–S99 через `POST /api/scenarios/custom`; `GET` повертає каталог, `DELETE /api/scenarios/custom/:id` видаляє файл. S01–S03 незмінні. Файли UTF-8 без BOM зберігаються в `server/data/custom-scenarios/` або `<DATA_DIR>/custom-scenarios/`, з правами 0600, через тимчасовий файл та атомарне перейменування. Ліміт — 50 сценаріїв по 256 KiB. Каталог не віддається як статика й не потрапляє до Git.

Сервер потребує `python3`: окремий процес використовує незмінені функції схеми та зв’язків із `zibraty.py`, обмежений п’ятьма секундами. Обидва рівні перевірки виконуються до запису; помилки не змінюють попередній файл. Биті файли при читанні пропускаються. Один процес сервера має обслуговувати один каталог даних.

Застосовано перевірку Origin/Referer, ліміти запитів і тіла, заборону небезпечних JSON-ключів, строгі ID та контроль шляху. Це спільний каталог довіреного LAN-хоста: окремих власників сценаріїв або нової ролі адміністратора немає, запис не вимагає локального акаунта. Не відкривайте API редагування у недовірену мережу без зовнішнього контролю доступу. Перевірка JSON не є юридичною експертизою; не вводьте ПД і службові матеріали.

Каталог завантажується з сервера при відкритті застосунку. Без сервера PWA показує вбудовані кейси; новий запис на диск недоступний. Користувацькі тексти відображаються мовою авторства та не замінюються вбудованими перекладами через збіг ID. UI підтримує UKR/ENG.

Кімната отримує копію сценарію на момент створення. Подальше редагування або видалення файла не змінює активну кімнату; повторне створення за видаленим ID заборонене. Дані копії передаються учасникам через наявний WebSocket; керування захищає `hostSecret`.

Перевірки: `npm test` охоплює диск, перезапуск, захищені ID, неправильний граф, CSRF, ізоляцію кімнати й очищення тимчасового каталогу. `node tests/custom-scenarios.browser.cjs` перевіряє повний цикл конструктора та модалку видалення в обох мовах і темах.

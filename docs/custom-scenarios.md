# Користувацькі сценарії

Конструктор зберігає S04–S99 через `POST /api/scenarios/custom`; `GET` повертає каталог, `DELETE /api/scenarios/custom/:id` видаляє файл. S01–S03 незмінні. Файли UTF-8 без BOM зберігаються в `server/data/custom-scenarios/` або `<DATA_DIR>/custom-scenarios/`, з правами 0600, через тимчасовий файл та атомарне перейменування. Ліміт — 50 сценаріїв; тіло запиту до 4 MiB, форматований файл до 2 MiB. Каталог не віддається як статика й не потрапляє до Git.

Runtime-валідатор Node.js читає незмінену `schema.json` та перевіряє ті самі інваріанти графа, що й `zibraty.py`; Python на хості для збереження не потрібен. `python3 zibraty.py` залишається обов’язковою перевіркою репозиторію. Обидва рівні серверної перевірки виконуються до запису; помилки валідації не змінюють попередній файл. Биті файли при читанні пропускаються. Один процес сервера має обслуговувати один каталог даних.

Застосовано перевірку Origin/Referer, ліміти запитів і тіла, заборону небезпечних JSON-ключів, строгі ID та контроль шляху. Це спільний каталог довіреного LAN-хоста: окремих власників сценаріїв або нової ролі адміністратора немає, запис не вимагає локального акаунта. Не відкривайте API редагування у недовірену мережу без зовнішнього контролю доступу. Перевірка JSON не є юридичною експертизою; не вводьте ПД і службові матеріали.

Каталог завантажується з сервера при відкритті застосунку. Без сервера PWA показує вбудовані кейси; новий запис на диск недоступний. Користувацькі тексти відображаються мовою авторства та не замінюються вбудованими перекладами через збіг ID. UI підтримує UKR/ENG.

Кімната отримує копію сценарію на момент створення. Подальше редагування або видалення файла не змінює активну кімнату; повторне створення за видаленим ID заборонене. Дані копії передаються учасникам через наявний WebSocket; керування захищає `hostSecret`.

Перевірки: `npm test` охоплює диск, перезапуск, захищені ID, неправильний граф, CSRF, ізоляцію кімнати й очищення тимчасового каталогу. `node tests/custom-scenarios.browser.cjs` перевіряє повний цикл конструктора та модалку видалення в обох мовах і темах.

## Діагностика збереження

Відкриття вбудованої задачі в конструкторі створює копію з новим ID. Перед атомарним записом каталог створюється повторно, навіть якщо його видалили після старту сервера. Успіх повертає HTTP 200; відмова — `error` та `details` з шляхом поля й кодом причини без абсолютних шляхів чи вмісту сценарію. Інтерфейс локалізує причини та показує їх під панеллю дій.

Регресійний тест запускає Express із порожнім `PATH`, щоб підтвердити відсутність runtime-залежності від Python, і зіставляє результати Node.js-валідатора з `zibraty.py` на коректних та некоректних даних. `node tests/builder-save.browser.cjs` перевіряє шаблон, клон S01, збереження, старт, видалення та відображення помилок на 375/1280 px у двох мовах і темах.

## Зображення та перенумерація

`POST` підтримує обгортку `{scenario, imageDataUrl?, removeImage?, revision?}`; старий формат чистого сценарію також приймається. PNG/JPEG/WebP перевіряються за MIME та сигнатурою; SVG заборонено. Декодований файл — до 2 MiB, дані зображення не потрапляють до JSON сценарію. Фото зберігаються окремо в `images/Sxx.<ext>` і видаються лише через контрольований API з `nosniff` та `no-cache`. Метадані з URL, ревізією та внутрішнім ключем задачі повертаються окремо від сценаріїв.

Видалення виконується в одній черзі з читанням/записом: решта задач та їхніх фото отримують послідовні ID від S04. Відповідь містить актуальний список і мапу перейменування. Історія локальних акаунтів та агрегати переміщуються за цією мапою; видалена історія не прив’язується до нового мешканця того самого номера. Гостьовий прогрес ізольований внутрішнім ключем задачі. Відкриті кімнати зберігають свою незмінну копію. Номер задачі є позицією каталогу, тому після видалення старі посилання потрібно перевірити.

UI передає ревізію при збереженні та видаленні, щоб застаріла вкладка не перезаписала переміщену задачу. У такому випадку API повертає HTTP 409. Модалка вимагає точну назву (з обрізанням крайніх пробілів), закривається через Esc, фон або × і очищує поле при закритті. Без підтвердження кнопка неактивна.

Перевірки: `tests/custom_images_tests.js` входить у `npm test`; `node tests/custom-image-renumber.browser.cjs` перевіряє завантаження фото, ширину кнопок, підтвердження, перенумерацію файлів і скидання наступного ID в UKR/ENG, Dark/Light на 375/1280 px.

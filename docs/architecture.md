# Архітектура рішення

Стан документації: 19 листопада 2026 року. Склад даних: 3 задачі, 26 вузлів, 102 варіанти, 64 норми.

## Компоненти та потоки

| Шар | Реалізація й відповідальність |
|---|---|
| Інтерфейс | React 18, TypeScript, Tailwind CSS, Vite; ліниве завантаження важчих маршрутів, UKR/ENG і Dark/Light |
| Дані | [Сценарії](../stsenarii/), [норми](../normy.json), [схема](../schema.json); переклади окремо в [src/i18n/](../src/i18n/) |
| Перевірка | [zibraty.py](../zibraty.py): структура, граф, ID та правові посилання; генерує [stsenarii.md](../stsenarii.md) і [perelik-norm.md](../perelik-norm.md) |
| Хост | Node.js, Express, `ws`; HTTP та WebSocket на одному порту для локальної мережі |
| Збереження | Локальний браузер для гостя; файлове сховище хоста для акаунтів/прогресу та окремого об’єкта агрегатів; кімнати лише в RAM |
| LMS | Клієнтський експорт SCORM 1.2 через динамічний імпорт JSZip |

Двигун знаходить вузол за ID, показує його варіанти та переходить за `nastupnyi_vuzol`. Вибір визначає заздалегідь записані наслідки й пояснення. LLM, зовнішніх AI API та генерації рішень у runtime немає. Конструктор редагує копію сценарію; це не серверний редактор спільної бази.

Кожен варіант має три значення від −2 до +2: `dobrochesnist`, `efektyvnist`, `dovira`. Зміни накопичуються лише всередині відповідної осі; спільного бала немає. SVG-маршрут показує колонки пройдених етапів, усі альтернативи й криву фактичних виборів. Повний граф конструктора показує також розгалуження. Таймер є навчальним орієнтиром: 0/10/15 хв, продовження після спливу дозволене. Панель CIDS містить п’ять перевірок для рефлексії, не автоматичний правовий висновок.

Груповий сервер синхронізує брифінг, раунди, голоси та розбір. Окремий `hostSecret` захищає керування. Голосування анонімне щодо акаунтів, але не посвідчує унікальність фізичної особи. Добровільні акаунти використовують псевдонім, `scrypt` і підписану HttpOnly-сесію. Агрегати завершених спроб не містять зв’язку з користувачами.

[Service Worker](../public/sw.js) спершу звертається до мережі для HTML/ресурсів, а за відмови використовує кеш. Vite вбудовує перелік усіх JS/CSS-чанків збірки. API/WS виключені з кешування. Для PWA потрібен захищений контекст; LAN через звичайний HTTP підтримує роботу із сервером, але не гарантує встановлення Service Worker.
